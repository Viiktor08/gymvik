# Gymvik — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** App PWA personal de entrenamiento (rutinas en rotación, sesión en directo sin conexión, progreso, creatina por NFC, pasos por Atajo, peso manual y avisos push) servida por un único Cloudflare Worker con D1.

**Arquitectura:** Un repositorio y un despliegue. Vite compila la app React y el Worker (Hono) sirve los estáticos y `/api/*`. La lógica de dominio son funciones puras en `src/shared` que usan tanto el front como el back. Una tarea programada cada 15 minutos calcula y envía los avisos.

**Stack:** TypeScript estricto · React 19 + react-router · Vite + `@cloudflare/vite-plugin` · Hono · Cloudflare D1 · zod · `@simplewebauthn/server` + `@simplewebauthn/browser` · recharts · idb · vite-plugin-pwa (`injectManifest`) · Vitest + `@cloudflare/vitest-pool-workers` + Testing Library + fake-indexeddb · push web compatible con Workers (`@block65/webcrypto-web-push` u otra basada en WebCrypto; comprobar al instalarla que funciona en `workerd`). Versiones: la última estable al instalar.

**Spec:** `docs/superpowers/specs/2026-11-09-gymvik-design.md` (leerla antes de empezar; este plan la implementa).

## Restricciones globales

- Un solo usuario. Sin registro público ni multiusuario.
- Identificadores de código en inglés. **Textos de la interfaz en español de España.**
- Zona horaria por defecto `Europe/Madrid`. La semana empieza el **lunes**. Todo "hoy" o "semana" se calcula con `src/shared/dates.ts`, nunca con `toISOString().slice(0,10)`.
- Unidades: kg, km y minutos. Los campos numéricos aceptan coma decimal ("57,5").
- Nunca se muestra `Infinity`, `-Infinity` ni `NaN`. Los agregados de listas vacías devuelven `null` y la interfaz muestra "—" o "Sin datos todavía".
- Peso y % de grasa **solo a mano**. El Atajo solo envía pasos.
- No se copia nada de Yulift (código, textos, animaciones ni marca). Las descripciones de ejercicios son propias.
- iOS ≥ 16.4 (push en PWA instalada). Node ≥ 20.
- Secretos (`SETUP_TOKEN`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`) solo en `wrangler secret` o `.dev.vars` (incluido en `.gitignore`).
- Cookie de sesión `__Host-session`. Claves de atajo con formato `fk_` + 32 bytes en base64url. Tokens, claves y códigos se guardan como hash SHA-256.
- Commits pequeños con Conventional Commits y `git push` al terminar cada tarea.

## Puntos a vigilar en la revisión

1. **Cambio de día y de hora:** un entreno a las 00:30 de Madrid (23:30 UTC) cuenta para el día de Madrid, también el fin de semana del cambio de hora → tests en las tareas 3 y 12.
2. **Ejercicios sin peso** (dominadas o plancha con el peso vacío o a 0) y entradas como "57,5": no rompen récords, volumen ni 1RM. Con peso 0 o vacío el 1RM es `null` → tests en las tareas 3 y 6.
3. **Entreno enviado dos veces** (sin cobertura se reintenta el mismo `PUT`): queda un solo entreno → test en la tarea 12.
4. **Estados vacíos** (sin rutinas en rotación, sin historial, sin pesos): `nextRoutine` devuelve `null`, récords y agregados son `null` y nunca aparece `Infinity` → tests en las tareas 4, 5, 6, 13, 18 y 22.
5. **Ejercicio archivado o rutina sacada de la rotación** después de usarlos: el historial los sigue mostrando y la rotación ignora la rutina sacada → tests en las tareas 4 y 11.

### Tarea 4: Rotación y duración estimada

**Archivos:** Crear `src/shared/rotation.ts` · Test `test/shared/rotation.test.ts`

**Interfaces:**
- Consume: `Routine`, `Workout`, `Exercise` (tarea 3).
- Produce: `nextRoutine(routines: Routine[], workouts: Pick<Workout,'routineId'|'startedAt'>[]): Routine|null` y `estimateDurationMin(routine: Routine, exercises: Map<string, Exercise>): number`.

`nextRoutine`: `rot` = rutinas con `inRotation && !archived`, ordenadas por `rotationOrder`. Si `rot` está vacía → `null`. Se busca el entreno más reciente (por `startedAt`) cuya `routineId` esté en `rot`. Si no hay ninguno → `rot[0]`. Si lo hay → la siguiente a esa rutina en `rot`, de forma circular.

`estimateDurationMin`: los ítems de fuerza suman `sets × (45 + restSeconds)` segundos. Los de cardio suman los minutos que aparezcan en `repsTarget` ("20 min" → 20; si no hay número, 10). El total se redondea al múltiplo de 5 más cercano, con un mínimo de 5.

  - Último hecho B → C. Último hecho C → A.
  - Historial B y después un entreno libre (`routineId` null) → C.
  - Historial A y después la rutina "Brazos", que no rota → B.
  - B sacada de la rotación (`inRotation:false`) con historial A y luego B → C, porque se ignora B y la última válida es A. Con B fuera y solo B en el historial → A.
  - Sin rutinas en rotación → `null`.
  - `estimateDurationMin` con 3 ejercicios de fuerza de 3 series y 90 s de descanso: 3·3·135 s = 20,25 min → 20.

### Tarea 5: Racha, progreso semanal y resumen

**Archivos:** Crear `src/shared/streak.ts`, `src/shared/weekly.ts` · Test `test/shared/streak.test.ts`, `test/shared/weekly.test.ts`

**Interfaces:**
- Produce: `weekProgress(workoutDates: string[], today: string): { count: number; days: boolean[] }` (días de lunes a domingo) y `streakWeeks(workoutDates: string[], goal: number, today: string): number`.
- Produce: `interface WeeklySummary { workouts: number; volumeKg: number; cardioMin: number; cardioKm: number; avgSteps: number|null; creatineDays: number }` y `weeklySummary(weekStartDate: string, data: { workouts: Workout[]; steps: { localDate: string; steps: number }[]; creatineDates: string[]; exercises: Map<string, Exercise> }): WeeklySummary`.

Reglas (spec §5.6):
- Una semana está cumplida si `count ≥ goal`, así que 4/3 cuenta como cumplida.
- La racha son las semanas cumplidas consecutivas contando hacia atrás desde la última semana cerrada, más 1 si la semana actual ya está cumplida. Una semana actual sin cumplir no rompe la racha.
- Volumen = Σ `weightKg × reps` de las series con ambos valores > 0, en ejercicios que no son de cardio.
- Cardio = Σ `durationMin` y Σ `distanceKm` en ejercicios con `category === 'cardio'`.
- `avgSteps` es la media de los días con datos, o `null` si no hay ninguno.

  - Lo mismo, pero la semana actual con 3 → 4.
  - La semana anterior con 2 → 0, o 1 si la actual ya está cumplida.
  - `weekProgress` con entrenos el lunes y dos el miércoles → `count 3` y `days [true,false,true,false,false,false,false]`.
  - Sin datos → `weeklySummary` = `{ workouts:0, volumeKg:0, cardioMin:0, cardioKm:0, avgSteps:null, creatineDays:0 }`.
  - Dominadas con `weightKg:null` no suman volumen ni producen `NaN`.

### Tarea 6: Récords y 1RM

**Archivos:** Crear `src/shared/records.ts` · Test `test/shared/records.test.ts`

**Interfaces:**
- Produce:
  - `epley1RM(weightKg: number|null, reps: number|null): number|null`
  - `interface SessionStats { maxWeight: number|null; best1RM: number|null; volume: number; maxDistance: number|null; bestPace: number|null }` (`bestPace` en min/km)
  - `sessionStats(we: WorkoutExercise): SessionStats`
  - `type RecordKind = 'maxWeight'|'best1RM'|'volume'|'maxDistance'|'bestPace'`
  - `newRecords(workout: Workout, previous: Workout[], exercises: Map<string, Exercise>): { exerciseId: string; kind: RecordKind; value: number }[]`
  - `exerciseRecords(exerciseId: string, workouts: Workout[]): Partial<Record<RecordKind, { value: number; localDate: string }>>`

Reglas:
- Epley: `w × (1 + r/30)`. Con `r === 1` el resultado es `w`. Con `w ≤ 0` o null, o con `r` null o 0, es `null`. Se redondea al 0,5 kg más cercano.
- `bestPace` es el mínimo de `durationMin / distanceKm` entre las series con distancia > 0 (menor es mejor).
- Un récord solo es **nuevo** si el ejercicio ya tenía historial y el valor lo supera. La primera vez que haces un ejercicio no se celebra.
- Récords de fuerza para `category !== 'cardio'` y récords de cardio para `'cardio'`.
